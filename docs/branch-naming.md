# Именование веток

## Формат

Основная ветка проекта — `main`. Для самостоятельных задач использовать короткоживущие ветки в формате:

```text
<type>/<short-kebab-description>
```

| Тип | Назначение | Пример |
| --- | --- | --- |
| `feat` | Новая функция или возможность API | `feat/uniq-by` |
| `fix` | Исправление поведения или публичных типов | `fix/pick-symbol-keys` |
| `perf` | Оптимизация с сохранением контракта | `perf/uniq-by` |
| `refactor` | Перестройка кода с сохранением контракта | `refactor/object-key-iteration` |
| `docs` | Документация | `docs/api-examples` |
| `test` | Самостоятельное улучшение тестов | `test/pick-type-inference` |
| `ci` | GitHub Actions и CI | `ci/node-matrix` |
| `chore` | Зависимости и обслуживание инструментов | `chore/update-dev-dependencies` |

## Описание задачи

- Использовать строчные латинские буквы, цифры и одиночные дефисы между словами. Между типом и описанием ставить один `/`.
- Описание должно быть коротким и конкретным, без дефиса в начале или конце.
- Имена API переводить в kebab-case: `uniqBy` → `uniq-by`, `mapValues` → `map-values`.
- Номер issue необязателен. Если задача существует, его можно добавить в начало описания: `feat/123-uniq-by`.
- Имя автора и дату добавлять не требуется.

## Работа с ветками

- Одна ветка соответствует одной самостоятельной задаче. Реализация функции, её тесты и документация входят в одну ветку, например `feat/uniq-by`.
- Изменения объединять в `main` через PR после code review и успешного CI.
- Отдельную `develop` на текущем этапе не использовать. Ветки `release/` и `hotfix/` вводить после определения процесса релизов и сопровождения.
- Примеры имён не являются поручением создать ветки или реализовать функции.

## Связь с другими соглашениями

Это соглашение проекта на основе формата [Conventional Branch](https://conventionalbranch.org/). Типы `perf`, `refactor`, `docs`, `test` и `ci` — расширения проекта, отсутствующие в базовой грамматике спецификации. При добавлении автоматической проверки явно учитывать их и согласованные исключения для ботов и инструментов.

[Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) относится к сообщениям коммитов. Имя ветки `feat/uniq-by` и сообщение `feat(array): add uniqBy` имеют разные форматы. Префикс ветки сам по себе не определяет версию пакета и не разрешает публикацию.

Допустимость имени для Git проверяется командой:

```sh
git check-ref-format --branch feat/uniq-by
```

Команда проверяет синтаксис Git, но не соблюдение соглашения проекта.
